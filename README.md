# make-knowledge-cards

一个 Codex Skill：把文章转成**可核查**的知识卡片。

## 1. 项目解决什么问题

把长文章压缩成几张卡片这件事，本身不难；难的是压缩之后你**没法验证它有没有走样**。

常见失败有两种，都很难被发现：

- **术语漂移。** 原文写“照明可能干扰夜间活动”，卡片写成“光照影响活动节律”。意思看着差不多，等到你要引用或复习时，卡片里的说法在原文里找不到出处。
- **边界脱落。** 原文说的是“只有在光照强度超过某阈值时”，卡片写成无条件规律。一个受条件限制的结论被悄悄放大成普遍结论，而且读起来更顺畅，所以更难察觉。

这个 Skill 的做法不是把规则写得更聪明，而是给每张卡片配一个**可机械核验的凭据**：命题切片（锚点）+ 原文原句引用。判断是否走样，因此从“你觉得意思对不对”降级为“逐字比对能不能对上”。同时，它把“这条信息该不该单独成卡”写成可执行的判定，而不是靠感觉决定拆几张。

它的能力边界很清楚：**它不发明内容**。文章没说的不补，例子、数字、因果链都不编。信息不够就少出几张，并说明原因。

## 2. 主要功能

- **先建文章地图，再出卡。** 先确定文章的核心问题与中心回答，卡片只保留解释这个回答所必需的因果、机制、条件、对比、流程和关键转折。
- **三种输入。** 粘贴正文、公开文章 URL、本地 `.md` / `.txt` 文件。
- **卡型区分。** 拆出的卡片按角色标注为 `主张卡`、`机制卡`、`对比卡`、`条件卡`、`证据卡`、`事件卡`。
- **锚点（命题切片）。** 每张拆分卡带一行 `锚点`：`[前置条件（如有） → 实体 → 动作 → 对象]`，每个成分逐字取自原文，禁止同义替换与泛化。
- **原文引用。** 每张拆分卡带一行 `原文引用`：原样复制包含锚点的原句，不改写、不拼接、不翻译——用来做逐字核验。
- **强制拆分。** 通过“独立命题 + 回答独立问题 + 新增学习价值”三项检查的信息必须拆成独立卡片，不允许留在母卡里当“可以分离”的附属内容。
- **条件与边界不脱落。** 限定某条机制的边界留在机制卡里，限定整体主张的留在主张卡里。
- **保真度保留。** `可能`、`相关`、`研究观察到`、`作者认为` 等表述保留原有强度与归属，不会被升格成确定的因果事实。
- **默认按原文语言输出。** 用户指定语言时按用户要求。
- **生成后自检。** 出卡前对草稿做一遍机械字符串检查（锚点词是否都出现在引用里、标题是否包含完整锚点串、引用是否为原话）。
- **人工核对点。** 输出末尾会提示用户抽查 `原文引用`——这是唯一能发现“读取阶段就已经改写术语”的环节。

不做的：PDF、Anki 导入导出、图形界面工作流；不抓取指定页面之外的页面，不用搜索摘要补正文，不绕过登录、付费墙或验证码。

## 3. 安装方法

Skill 的载体就是 `SKILL.md`，安装等于把它放到 Codex 会扫描的技能目录下：

1. 取得本目录：`skills/make-knowledge-cards/`（含 `SKILL.md`、`agents/openai.yaml`、`references/CHECKLIST.md`）。
2. 放到技能根目录之一：
   - 用户级：`C:\Users\<你>\.codex\skills\make-knowledge-cards\`（个人全局可用）；
   - 项目级：`<项目>\.agents\skills\make-knowledge-cards\`（只在该项目内可用）。
3. 重启 Codex 或新开一个会话，让它重新扫描技能目录。
4. 在会话里用 `$make-knowledge-cards` 调用。

需要说明的三点，避免误解：

- 本仓库**不含** `quick_validate.py`（它随 Codex 的 skill-creator 提供）、不含安装脚本、不含 Git 仓库、也没有上架任何市场——所以没有 `npm install` 之类的安装命令，也不需要。
- `references/CHECKLIST.md` 是评审用的第二层材料，**可选**：不复制它，Skill 仍然可用，只是人工复核时少一份门槛清单。但 SKILL.md 正文有引用它，建议一起复制。
- 上面走的是 Codex 的目录约定；是否能被其他 agent 运行时识别，取决于该运行时自己的技能机制——本仓库没有对它们做过验证。

## 4. 使用方法

在会话中调用 `$make-knowledge-cards`，然后给它输入：

- **粘贴正文：** 直接把文章文本贴进来。
- **公开文章 URL：** 给出链接，Skill 用可用的网页读取工具读取该页正文；页面读不到、读不全或需要登录/付费时，它会停下并向你要正文或本地文本，**不会**用搜索摘要去补。
- **本地文件：** 提供 `.md` 或 `.txt` 文件路径（本地路径权限由你与 agent 的会话决定）。

输出语言默认跟随原文主要语言；指定语言时按你要求的语言。适合的文章类型：说明文、教程、评论与观点文、叙事性文本。

一次完整流程长这样：

```text
你：$make-knowledge-cards  https://example.com/some-article
    （或者 你：$make-knowledge-cards  然后把正文粘进下一条消息）

Skill：
  文章主线
    - 核心问题/主题：……
    - 中心回答/发展：……
  1. 主张卡：……
     - 锚点 / 核心知识 / 简明解释 / 原文引用 / 理解线索……
  2. 机制卡：……
     ……
  （末尾一行提示：原文引用是给人抽查用的）
```

想核对某张卡是否忠实，只需要做一件事：把 `原文引用` 里的那句话拿回原文搜一次，逐字比一遍。

## 5. 输入输出示例

**输入文章（粘贴的短文）：**

> 一项观察研究发现，夜间照明时间较长的街区，某昆虫的出现率较低。研究团队认为，照明可能干扰这种昆虫的夜间活动；但这项观察只能显示相关性，无法证明照明是唯一原因。

**输出：**

## 文章主线
- **核心主题：** 夜间照明与该昆虫出现率之间的关系。
- **中心回答：** 观察研究发现两者相关；研究团队提出了可能的活动干扰解释，但研究不能证明唯一原因。

### 1. 主张卡：夜间照明时间与昆虫出现率呈负相关
- **核心知识：** 研究观察到，照明时间较长的街区中，该昆虫的出现率较低。
- **简明解释：** 这是观察到的相关关系，不足以单独证明照明造成了出现率下降。
- **原文限制：** 研究无法证明照明是唯一原因。

### 2. 机制卡：照明可能干扰该昆虫的夜间活动
- **锚点：** `[照明 → 可能干扰 → 夜间活动]`
- **核心知识：** 研究团队认为，照明可能干扰这种昆虫的夜间活动。
- **简明解释：** 该解释用于理解观察到的相关性，原文没有将它表述为已证实的因果机制。
- **原文引用：** “研究团队认为，照明可能干扰这种昆虫的夜间活动”
- **作者观点：** 这是研究团队的判断。

这段短文只支持两个独立知识点，因此示例没有强行扩展到五张。注意锚点里保留了“可能”——模态词也是限定成分，丢掉它会把“可能干扰”升格成“干扰”。

## 6. 拆卡与锚点规则（实现细节）

通过“独立命题 + 回答独立问题 + 新增学习价值”三项检查的信息，**必须**拆成独立卡片，不再写成“可以分离”这种留有余地的说法。每张拆出的卡片都要带两行可核验的内容：

- **锚点：** `[前置条件（如有） → 实体 → 动作 → 对象]`，每个成分都逐字取自原文，禁止同义替换（`照明` 不能写成 `光照`，`干扰` 不能写成 `影响`、`打断`，`夜间活动` 不能写成 `活动节律`）。限定成分只要影响命题是否成立，就必须留在锚点里。
- **原文引用：** 原样复制包含该锚点的原句，加引号，不改写、不拼接、不翻译。它的作用是把“是否忠于原文”从语义判断降级成逐字比对。

机制卡的标题必须逐字包含整条锚点串；主张卡被拆走后只保留锚点与依赖关系名，推导过程留在子卡上。

## 7. 代价与校验

**代价：** 带锚点和原文引用意味着输出比普通摘要更长、更重复，机制或条件较多的文章尤其明显。这是为了让术语和边界可被机械核验而付出的固定成本，不属于可以顺手省掉的冗余。

**校验：** 内部字符串比对只能保证卡片之间不失联，**不能**发现模型在提取阶段就把 `干扰` 写成 `影响` 这类源头漂移——因为比较的两端都出自同一次输出。忠实度只能靠人工抽查 `原文引用` 与原文是否逐字吻合，Skill 会在输出末尾提示这一点。

**验证 Skill 文件本身：** 本仓库不含官方 `quick_validate.py`（它随 Codex 的 skill-creator 提供）。改动 SKILL.md 后可用它复验：

```powershell
python "<skill-creator>\scripts\quick_validate.py" "<本仓库>\skills\make-knowledge-cards"
```

该脚本需要 PyYAML，且**只检查 frontmatter**：`---` 包裹、`name`/`description` 存在且合法、无 `[TODO:` 占位。正文内容不会被它检查。
